## 우리 근거

### 역할 분담

| 이름 | 소속 전공 | 역할 | 맡은 것 |
| --- | --- | --- | --- |
| 이승석 | (채울 것) | 팀장 · PM · 프론트엔드 · 발표 | 제품 결정, 화면, 발표 |
| 이고은 | (채울 것) | 프론트엔드 | 화면 구현 |
| 이준혁 | (채울 것) | 기술 총괄 · 백엔드 | 아키텍처, 판정 API |
| 윤혜빈 | (채울 것) | 백엔드 | API 구현 |
| 한원탁 | (채울 것) | **데이터 총괄** · 데이터베이스 | 스키마, 적재 |
| 최현성 | (채울 것) | 데이터 수집 · 데이터베이스 관리 | 원자료 수집, 정규화 |

역할은 셋으로 갈린다. **제품·화면 / 서버·판정 / 데이터**.

데이터를 따로 둔 이유가 있다. PSIS·NCPMS 원자료는 그대로 못 쓴다.
「수확7일전」「정식기」「파종(정식)일부터14일」 같은 **글자를 숫자로 바꾸는 일**이 먼저다.
이 작업의 결과가 판정 규칙을 정했다 (02 문서의 빈칸 세 갈래).
서버팀이 이 판단을 같이 했으면 「값이 없으니 통과」로 갔을 것이다.

**소속 전공 칸이 비어 있다.** 앵커·COSS 전공 간 구성을 적어야 한다.

### 협업 결과 — 전공이 섞여서 나온 산출물

현재 말할 수 있는 것:

| 산출물 | 어떤 섞임인가 |
| --- | --- |
| 빈칸 세 갈래 분류 | 데이터 해석 + 농학 지식 + 제품 판단이 함께 필요했다 |
| 4체크 설계 | 법 기준(①②③)과 농학 기준(④)을 분리한 것 |
| 계통 사용 비중 | 작용기작(농학) 개념을 기록 데이터(개발)로 계산 |

그런데 **이게 전공 간 협업의 결과라고 말할 근거가 지금 없다.**
전원이 컴퓨터공학 계열이면 융합성 점수가 거의 안 나온다.
