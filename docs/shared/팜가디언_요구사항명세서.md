## 1. 문서 목적과 범위

이 문서는 [팜가디언 PRD](팜가디언_PRD.md)의 기능별 동작·예외·수락 기준(완료를 확인할 조건)을 정의하는 팀 검토용 문서다. 기능 범위·우선순위는 PRD를 따르며, 적용 대상은 감자·배추·토마토다.

미확정 기준은 8절에서 관리한다. 구현 방법은 API 명세·테크스펙, 업무 배정은 WBS·백로그에서 관리한다. 개발 중 요구 동작을 변경하면 이 명세서도 함께 갱신한다.

기능 요구사항은 25개, 비기능 요구사항은 8개다. 기능·비기능 명세서로 옮길 때는 개별 구현과 동작 확인이 가능한 단위로 기능 행을 나눈다. 같은 FR에 속해도 동작과 수락 기준이 다르면 여러 행으로 작성할 수 있다. 예를 들어 FR-102는 균등 분할·직접 선 그리기·경계 수정으로 나누되 원래 FR ID를 유지한다. 화면별로 나누거나 모든 클릭을 별도 기능으로 만들지는 않는다.

표에는 기능 구분·세부 구분·기능명·FR ID·설명·우선순위를 두고, 입력·처리·출력·예외·수락 기준은 각 기능 페이지 본문에 둔다. 용어·공통 규칙·화면 매핑·미확정 사항은 공통 문서 영역에서 함께 관리한다.

**범위에 포함**

- P0: 밭·구역 등록, 병해충 도감·기본 이름 검색·매개충 안내, 네 개의 체크, 근거·대안, 실제 살포 기록·과거 이력 직접 입력·조회·취소, 구역별 계통 사용 비중, 기본 날씨 표시.
- P1: 포장지 OCR을 통한 살포 이력 입력 보조, 희석 계산, 논문 실측값 표시.
- P2: 행정구역별 계통 사용 비중 지도.

**범위에서 제외** (개발하지 않음)

- 사진 기반 병해충 진단 모델
- 병해충 발생 예측 모델
- 수확 시기 예측
- 저항성 수준 측정·예측
- 관수·시설 제어

사용 예정·재고 관리, 날씨를 반영한 별도의 살포 가능 판정, 상담사 전용 계정·관리자 화면도 현재 범위에 포함하지 않는다.

## 3. 우선순위 정의


| 등급  | 의미      | 판단 기준                            |
| --- | ------- | -------------------------------- |
| P0  | 첫 버전 필수 | PRD에서 첫 버전에 포함하기로 정한 기능          |
| P1  | 추가 검토   | P0 완료 후 일정·준비 상태를 보고 채택한다        |
| P2  | 고도화 | 기본 서비스 완성 후 별도 착수 합의로 진행할 기능 |
| 미확정 | 검토 중    | 표본·팀 의견을 확인하기 전 필수 기능으로 간주하지 않는다 |


**P1 이하가 전부 실패해도 P0만으로 데모가 가능해야 한다.** 개발 순서는 P0 완료 후 P1이다.

## 4. 공통 규칙

판정 상태·하드 룰·표기 규칙은 판정 관련 요구사항에 적용한다. 저장 실패·재시도 규칙은 밭·구역·작물 정보와 살포 기록의 저장·취소에 적용한다.

### 4.1 판정 상태


| 상태    | 내부 코드     | 화면 표기 | 의미                                       |
| ----- | --------- | ----- | ---------------------------------------- |
| 가능    | `GREEN`   | 가능    | 4체크 전부 통과. 근거가 확정된 경우에만 부여한다             |
| 주의    | `AMBER`   | 주의    | 확인된 반복규칙을 초과한 계통 사용. 사유와 다른 계통의 대안을 표시한다 |
| 불가    | `RED`     | 불가    | ①②③ 중 하나 이상 위반                           |
| 확인 필요 | `UNKNOWN` | 확인 필요 | 판정 근거가 부족하다                              |


**최종 상태는 4개 체크 중 가장 낮은 등급을 따른다.** 우선순위는 `RED` &gt; `UNKNOWN` &gt; `AMBER` &gt; `GREEN`.

### 4.2 하드 룰

위반하면 결함으로 처리한다.

1. 살포 이력이 0건인 구역에서 ③횟수·④작용기작을 `GREEN`으로 판정하지 않는다. `UNKNOWN`으로 반환한다.
2. 병해충 미선택이면 ①등록은 `UNKNOWN`으로 반환한다. ②③④는 각자 필요한 정보로 판단한다.
3. 안전사용기준 파싱에 실패한 행은 해당 체크를 `UNKNOWN`으로 반환하고 원문을 그대로 노출한다.
4. `RED`·`AMBER` 판정에는 작용기작이 다른 대안 약제를 함께 반환한다.
5. 「농업기술센터 문의」 안내는 대안 약제가 0개일 때만 출력한다.
6. 판정 응답에는 항상 근거 원문과 데이터 기준일이 포함된다. 근거 없는 판정은 반환하지 않는다.
7. 수확 가능일은 일수가 아니라 날짜로 반환·표시한다.

빈 기준값을 임의로 제한 없음으로 해석하지 않는다. 생육단계 등 추가 조건을 확인할 정보가 없으면 해당 체크는 확인 필요이며, 다른 체크는 각자의 근거로 판단한다. 약제는 목록에서 확인할 수 있게 한다.

### 4.3 작용기작 표기 규칙

화면에는 국내 표기를 앞에, 국제 코드를 괄호로 뒤에 쓴다.

```
표기:  가1 (FRAC 4)
금지:  FRAC 4
```

농약 포장 전면에 인쇄되는 것은 국내 표기다. 국제 코드만 표시하면 사용자가 대조할 수 없다.


| 용도  | 국내 표기           |
| --- | --------------- |
| 살균제 | 한글 (가, 나, 다 …)  |
| 살충제 | 숫자 (1, 2, 3 …)  |
| 제초제 | 알파벳 (A, B, C …) |


### 4.4 날짜 표기 규칙

기간이 아니라 날짜로 표기한다.

```
표기:  9월 21일부터 수확 가능
금지:  수확 21일 전까지
```

### 4.5 금지 표현


| 금지         | 대체                           |
| ---------- | ---------------------------- |
| AI가 진단한다   | 사용자가 병해충을 선택한다 / 공공데이터를 조회한다 |
| 저항성을 예측한다  | 로테이션 규칙 준수 여부를 카운트한다         |

| 추천         | 판정 결과 제시                     |

### 4.6 저장 실패·재시도 규칙

저장·취소 결과를 정확히 안내하고 같은 작업이 중복 반영되지 않도록 한다. 저장 여부를 확인하는 방법과 화면 구성은 구현·검증 과정에서 정한다. 저장 상태는 네 개의 체크의 판정 상태와 구분한다.

**동작 기준**

- 필수 항목 오류·미저장으로 확인된 실패 시, 문제가 된 항목을 안내하고 현재 화면의 나머지 입력값을 유지한다. 수정하거나 재시도할 수 있다.
- 저장 중임을 표시하고 같은 작업의 연속 제출을 막는다. 성공이 확인되기 전에 저장 완료를 안내하지 않는다.
- 응답이 끊겨 저장 여부가 불명확하면 「저장 결과를 확인하지 못했습니다」라고 안내하고 입력값을 유지한다. 결과를 다시 확인할 경로를 제공한다.
- 재확인 결과 이미 저장되어 있으면 기존 결과를 표시하고, 미저장이 확인되면 재시도할 수 있다. 계속 확인할 수 없으면 결과 확인 필요 상태를 유지한다.
- 같은 저장 작업의 재시도는 기록·집계에 한 번만 반영한다. 같은 구역·약제·날짜라도 실제 별도 살포 건과는 구분한다. 별도 살포 건의 중복 후보 확인은 FR-401의 사용자 확인 흐름을 따른다.

**적용 범위**

- 입력값 유지는 오류가 난 현재 화면을 기준으로 한다. 새로고침·앱 종료 후 복원, 오프라인 자동 저장은 별도 요구사항으로 정하지 않았다.
- 취소에도 적용한다. 취소 성공을 확인하기 전 완료로 안내하지 않고, 불명확하면 취소 여부를 다시 확인한다.

**수락 기준**

- 필수 항목 오류 또는 미저장이 확인된 실패 후 입력값을 다시 입력하지 않고 수정·재시도할 수 있다.
- 같은 저장 작업을 여러 번 시도해도 기록·집계에 한 번만 반영된다.
- 저장·취소는 완료됐지만 응답이 끊긴 사례에서, 재확인 후 기존 결과를 표시하고 기록·집계를 중복 변경하지 않는다.
- 결과를 확인할 수 없는 동안 성공·실패를 임의로 안내하지 않는다.

### FR-101 밭 등록

**우선순위** P0

**입력**

- 주소 문자열 (도로명 또는 지번)

**처리**

1. 입력한 주소에 해당하는 팜맵의 실제 경작 경계를 조회한다.
2. 후보 필지가 여러 개면 표시하고 사용자가 선택한다.
3. 선택한 경계와 면적을 밭 정보로 저장한다.

**출력**

- 필지 폴리곤이 그려진 화면
- 필지 면적 (ha)

**예외**

- 팜맵 조회 결과 0건: 「해당 주소에서 농경지를 찾지 못했습니다」 안내 후 주소 재입력 유도
- 팜맵 API 응답 실패: 오류 안내 후 재시도 버튼 제공. 등록 단계이므로 서비스 전체가 중단되지 않는다

**수락 기준**

- 실제 주소를 입력하면 지적도가 아닌 실제 경작 경계가 표시된다
- 필지가 여러 개인 경우 사용자가 선택할 수 있다

### FR-102 구역 분할

**우선순위** P0

**입력**

- FR-101에서 확정된 필지 폴리곤
- 균등 분할 시: 분할 개수와 방향
- 직접 분할 시: 사용자가 그린 분할선
- 분할 후 수정할 경계 위치

**처리**

1. 팜맵 API로 조회하고 FR-101에서 확정한 실제 경작 경계 위에서 구역을 나눈다.
2. 균등 분할을 선택하면 사용자가 분할 개수와 방향을 지정하고, 선택한 방향으로 면적이 같은 구역의 분할안을 확인한다.
3. 직접 분할을 선택하면 사용자가 경작 경계 위에 선을 그려 원하는 구역을 나눈다.
4. 두 방식 모두 분할 후 경계를 드래그해 수정할 수 있다. 수정할 때 구역별 면적을 다시 계산해 표시한다. 경계를 수정한 뒤에는 균등 면적을 유지할 필요가 없다.
5. 각 구역에 이름을 부여한다 (기본값 A, B, C, D …).
6. 사용자가 최종 경계·이름·면적을 확인한 뒤 저장한다.

**출력**

- 구역이 나뉜 필지 화면
- 구역별 면적

**예외**

- 분할하지 않으면 필지 전체가 단일 구역이 된다
- 구역이 겹치거나 빈 구역·경작 경계 밖 영역이 생기는 등 유효하지 않은 분할은 저장하지 않고 수정할 위치를 안내한다

**수락 기준**

- 분할 개수와 방향을 선택하면 균등 면적의 분할안을 확인할 수 있다. 균등 면적의 허용 오차는 측정·팀 검토 후 확정한다.
- 선 그리기로 구역을 나누고, 두 분할 방식에서 만들어진 경계를 드래그해 수정할 수 있다
- 수정한 경계에 맞춰 구역별 면적이 갱신되고, 최종 경계·이름·면적이 저장된다
- 분할 구역은 서로 겹치지 않고 필지 전체를 포함한다. 구역별 면적 합과 필지 전체 면적을 비교할 수 있으며, 면적 합의 허용 오차는 측정·팀 검토 후 확정한다.
- 분할하지 않아도 필지 전체를 단일 구역으로 등록하고 다음 단계로 진행할 수 있다

**비고**
살포 이력은 구역 단위로 관리된다. 한 필지에서 작물을 달리 심는 경우 ③횟수·④작용기작이 섞이지 않게 하려는 것이 분할의 목적이다.

### FR-103 구역별 작물·정식일 지정

**우선순위** P0

**입력**

- 구역 ID
- 작물 (목록에서 선택)
- 정식일 (날짜, 선택)

**처리**

1. 대상 작물 목록에서 작물을 선택한다.
2. 정식일은 입력을 권하되, 미입력 상태로도 저장한다. 나중에 추가할 수 있다.
3. 정식일을 추가·수정해도 기존 살포 기록의 실제 날짜·구역·약제는 보존한다.
4. 변경한 재배 기간에서 포함되는 기록과 기간 밖 기록을 구분해 사용자가 확인할 수 있게 한다. 기간 밖 기록도 삭제하지 않고 목록에서 확인할 수 있게 한다.
5. 변경한 기간과 이력에 따라 확인 가능한 집계를 다시 계산한다. 날짜 변경만으로 누락 이력이나 기간 귀속이 해결됐다고 간주하지 않는다.

**출력**

- 구역별 작물명, 정식일 또는 미입력 상태

**예외**

- 정식일 없이 적용할 수 있는 사용기준이면 ② 수확 가능 날짜를 계산한다. 필요한 추가 조건을 확인할 수 없으면 ②는 `UNKNOWN`이다.
- 이번 재배 기간을 구분할 정보가 없으면 ③은 `UNKNOWN`이다. ④도 해당 반복규칙에 필요한 정보가 부족하면 `UNKNOWN`이다.

**수락 기준**

- 정식일을 입력하지 않아도 등록할 수 있고, 나중에 날짜를 추가할 수 있다
- 정식일만 없고 다른 사용조건의 근거가 충분한 사례에서 ②를 일괄적으로 `UNKNOWN`으로 처리하지 않는다
- 필요한 재배 기간·이력이 부족하면 ③④의 해당 결과에 부족한 정보를 표시한다
- 정식일을 추가·수정해도 기존 기록은 삭제되거나 실제 살포 날짜가 바뀌지 않는다
- 변경된 기간의 포함·제외 기록을 확인할 수 있으며, 기간 귀속을 확인하지 못한 기록은 관련 판정에서 충분한 근거로 간주하지 않는다

### FR-202 병해충 후보 제시

**우선순위** P0

**입력**

- 구역의 작물
- 오늘 날짜 (월, 발생시기 참고 표시용)
- 증상 부위 (FR-201, 선택)

**처리**

1. 해당 작물의 도감 후보를 조회하고, 선택한 증상 부위를 참고해 목록을 좁힌다.
2. 발생시기는 출처·기준 시점과 함께 참고 정보로 표시한다. 발생시기만으로 후보를 제외하지 않는다.
3. 사진·증상 정보가 있으면 표시한다. 정보가 없으면 없다고 표시한다.
4. 기본 이름 검색으로도 병해충을 찾을 수 있게 한다. 도감에는 없지만 수집한 등록약 자료에 있는 병해충은 FR-204로 선택할 수 있다.

**출력**

- 병해충 후보 목록 (이름, 확인된 사진·설명, 발생시기 참고 정보, 출처·기준 시점)

**예외**

- 선택한 부위의 후보 0건: 정보 없음 안내와 해당 작물 전체 목록·이름 검색 경로 제공
- 발생시기·사진·설명 없음: 후보를 숨기지 않고 해당 정보 없음 표시

**수락 기준**

- 확신도 백분율을 표시하지 않는다
- 발생시기에 해당하지 않거나 발생시기 자료가 없다는 이유로 병해충을 선택할 수 없게 하지 않는다
- 과거 발생정보를 현재 경보로 표시하지 않는다
- 대체·보충 사진은 실제 사진의 작물과 출처를 표시한다

**수락 기준**

- 병해충 미선택이면 ①은 `UNKNOWN`, ②③④는 각자의 근거로 판단한다

### FR-204 병해충 이름 검색

**우선순위** P0

**입력**

- 구역의 작물 ID
- 검색어 (부분 문자열)

**처리**

1. 해당 작물의 도감·등록정보에 연결된 병해충의 이름·확인된 별칭을 부분 일치로 검색한다.
2. 도감에는 없지만 수집한 등록약 자료에 있는 병해충도 결과에 포함한다.
3. 사용자가 결과에서 병해충을 직접 선택한다.

**출력**

- 병해충 이름과 선택 가능한 항목, 도감 정보의 유무

**예외**

- 검색 결과 0건: 다른 검색어 입력, 해당 작물의 도감 확인 또는 병해충 미선택 진행 경로를 제공한다
- 사진·설명이 없어도 이름과 등록정보가 확인된 항목은 선택할 수 있다

**수락 기준**

- 사전에 존재하지 않는 병해충명을 반환하지 않는다
- 해당 작물의 도감에 없고 등록정보만 있는 병해충을 검색·선택할 수 있다

### FR-205 바이러스·매개충 안내

**우선순위** P0

**입력**

- 구역의 작물, 사용자가 선택한 바이러스 항목

**처리**

1. 원자료와 대조한 해당 작물·바이러스의 매개충 연결만 조회한다.
2. 매개충 정보와 근거 출처를 표시한다.
3. 사용자가 매개충을 직접 선택하면 해당 작물·매개충의 등록 약제 목록과 네 개의 체크로 연결한다.

**출력**

- 매개충 이름·연결 근거, 사용자가 선택한 실제 판정 대상

**예외**

- 확인된 연결 없음: 연결 자료 없음으로 표시한다. 임의의 매개충으로 바꾸지 않는다.
- 선택한 매개충의 등록 약제 없음: 등록 약제 없음으로 표시한다. 문의 안내는 대안이 0개인 경우에만 적용한다.

**수락 기준**

- 사용자가 선택하지 않은 매개충을 판정 대상으로 자동 확정하지 않는다
- 선택한 작물·매개충에 대한 등록조건을 확인하며, 바이러스에 등록된 약제로 표시하지 않는다
- 매개충 약제의 사용조건을 바이러스 치료 효과로 설명하지 않는다

### FR-301 등록 약제 목록 조회

**우선순위** P0

**입력**

- 작물 ID
- 병해충 ID (선택)

**처리**

1. 선택한 작물·병해충에 해당하는 등록 약제와 사용기준을 조회한다.
2. 병해충 미선택이면 작물 조건만으로 조회하되 ①등록은 확인 필요로 표시한다.
3. 약제 정보·작용기작 코드·사용기준을 함께 제공한다.

**출력**

- 약제 목록 (상표명·품목명·회사명, 작용기작 국내·국제 코드, 확인된 사용기준, 원문, 기준일)

**예외**

- 결과 0건: 「등록된 약제가 없습니다」 안내 및 농업기술센터 문의 안내

**수락 기준**

- 약제 목록의 출처는 PSIS 안전사용기준이다. 병해충 도감의 방제법 텍스트를 사용하지 않는다
- 판정할 약제는 제품명 검색·목록 선택으로 고를 수 있다. 포장지 OCR은 P1 이력 입력 화면의 보조 기능으로 둔다.
- 기준이 비어 있거나 원문 해석에 실패한 약제도 목록에서 원문과 확인 필요 사유를 확인할 수 있다

### FR-302 4체크 판정

**우선순위** P0

**입력**

- 구역 ID
- 약제 ID
- 병해충 ID (선택)
- 기준 날짜 (기본값 오늘)

**처리**

각 체크는 아래 기준으로 계산하며 FR-303의 일관성 조건을 따른다. ③④는 선택한 약제를 이번에 1회 사용한다고 가정해 확인하며, 이 가정 자체를 살포 이력으로 저장하지 않는다.

**① 등록**

```
조건: 기준 날짜에 해당 작물·병해충·약제 조합의 유효한 등록이 확인됨
결과: 조건 충족 GREEN, 확인된 등록조건 미충족 RED, 병해충 미선택 또는 필요한 근거 부족 UNKNOWN
```

**② 시기**

```
계산: 수확가능일 = 기준 날짜 + 확인된 수확 전 일수
결과: 수확 전 일수와 필요한 추가 사용조건의 충족이 확인되면 GREEN
      파싱 실패, 필요한 기준값 또는 추가 조건 정보 부족이면 UNKNOWN
      정식일 없음만을 이유로 UNKNOWN으로 처리하지 않는다
출력: 수확가능일 (날짜 형식)
```

추가 사용조건의 위반이 확인된 경우와 정보를 확인할 수 없는 경우를 구분해야 한다. 어떤 원자료 조건을 ②에서 평가하고 불가로 처리할지는 원자료·입력 정보 검증 후 확정한다. 확정 전에는 해당 조건을 임의로 통과시키지 않는다.

**③ 횟수**

```
전제: 해당 구역·이번 재배 기간의 유효 이력과 사용한도가 충분히 확인됨
계산: 현재 남은 횟수 = 최대 사용횟수 - 기존 사용횟수
      이번 사용 포함 횟수 = 기존 사용횟수 + 1
      이번 사용 후 남을 횟수 = 최대 사용횟수 - 이번 사용 포함 횟수
결과: 이번 사용 포함 횟수 <= 최대 사용횟수이면 GREEN, 초과하면 RED
      이력 0건, 재배 기간 또는 최대 사용횟수 등 필요한 근거 부족이면 UNKNOWN
출력: 현재 남은 횟수와 이번 사용 후 남을 횟수를 구분
```

이번 재배 기간의 살포 기록을 확인할 때 사용자에게 기록 누락 여부를 확인한다. 누락이 있거나 누락 여부를 확인하지 못하면 관련 ③④에 확인 필요 사유를 표시한다. 사용자가 누락이 없다고 답한 것만으로 재배 기간·약제·규칙 등 필요한 근거가 모두 확인됐다고 간주하지 않는다.

사용횟수는 **성분 단위로 합산한다** (2026-10-15 확정). 상표·품목이 달라도 성분이 같으면 같은 약으로 센다. 혼합제는 성분마다 1회씩 센다. 한도는 이번에 쓸 약과 이력 약들의 최대 횟수 중 가장 작은 값이며, 혼합제는 성분마다 따로 계산해 하나라도 한도에 닿으면 불가로 본다. 계산 규칙은 [DB 시드 전달서 4절](../technical/DB_시드_전달서.md)에 있다.

계산에 충분한 이력의 범위는 원자료·규칙 검증 후 확정한다. 일부 기록의 입력만으로 전체 이력이 충분하다고 간주하지 않는다.

**④ 작용기작**

```
계산: 해당 구역의 유효 이력에 이번 약제 사용 1회를 가정해 더한다
      적용할 규칙의 최근 사용·연속 사용·재배 기간 조건에 맞춰 계통 사용을 센다
결과: 근거가 충분하면 규칙 미초과 GREEN, 규칙 초과 AMBER
      이력 0건, 계열·규칙·필요한 재배 기간 정보 부족이면 UNKNOWN
출력: 국내·국제 코드, 기록된 사용횟수, 이번 사용 포함 결과, 적용 규칙의 범위
```

혼합제·미분류 계열, 반복규칙 충돌과 계산에 충분한 이력의 범위는 원자료·규칙 검증이 필요하다. 기록 누락 여부의 확인은 ③과 같은 흐름을 따르며, 확인할 수 없는 조건을 임의로 통과시키지 않는다.

**출력**

- 최종 상태와 체크별 상태·사유·근거 원문·데이터 기준일
- 수확 가능 날짜, 현재 남은 횟수, 이번 사용 후 남을 횟수, 계통 사용 결과
- 불가·주의인 경우 다른 계통의 대안

**예외**

- 하드 룰 1~7이 모두 적용된다

**수락 기준**

- 기준 날짜에 해당 등록이 취소된 것으로 확인되면 ①등록은 불가로 표시된다
- 이력 0건 구역에서 ③④가 `UNKNOWN`으로 반환된다
- 병해충 미선택이면 ①은 `UNKNOWN`, ②③④는 각자의 근거로 판단한다
- ② 결과가 날짜 형식으로 반환된다
- ④ 결과에 백분율이 포함되지 않는다
- 각 체크에 확보한 근거 원문·데이터 기준일과 필요한 정보의 부족 사유를 표시한다. 자료가 없는 체크는 「확인 필요: 사용기준 자료 없음」 등 해당 사유를 표시한다. 없는 원문·출처·기준일을 만들거나 통과로 처리하지 않는다. 상세 표시는 FR-305를 따른다.
- 최대 3회·기존 2회인 검증 사례에서 이번 사용은 허용 한도 이내이며, 사용 후 잔여 0을 이유로 이번 사용을 불가로 처리하지 않는다
- 판정 조회를 반복해도 실제 기록과 기존 사용횟수는 늘지 않는다

### FR-303 판정 결과의 일관성

**우선순위** P0

**적용 범위** FR-302의 모든 판정에 적용하는 공통 동작 기준이다. 별도의 화면이나 사용자 조작을 뜻하지 않는다. NFR-02·03의 품질 조건과 연결하며, FR-304는 계산된 결과를 목록에 정렬·표시하는 기능이다.

**입력**

- 구역·작물 정보, 선택한 약제·병해충, 기준 날짜, 유효한 살포 이력, 적용할 사용기준·반복규칙과 데이터 기준일

**요구 동작**

- 동일 입력과 동일한 원자료·규칙으로 동일한 판정 결과를 제공한다.
- 판정은 확인된 원자료와 규칙 계산으로 수행한다. 판정 요청 중 추론 모델을 호출하지 않는다.
- 판정은 이미 준비한 데이터로 수행하며, 외부 공공 API·OCR의 실시간 성공 여부에 의존하지 않는다.
- 각 체크에 근거 원문·데이터 기준일을 제공하고, 정보가 부족하면 해당 체크를 확인 필요로 표시한다.

**출력**

- 네 개의 체크별 상태·사유와 최종 상태, 근거 원문·데이터 기준일

**수락 기준**

- 같은 입력·원자료·규칙으로 반복 확인하면 결과가 동일하다
- 이력 0건·병해충 미선택·원문 해석 실패와 확인된 기준 위반의 시험 사례가 공통 규칙에 맞는 결과를 제공한다
- 외부 공공 API·OCR 장애를 재현해도 이미 준비된 자료를 이용하는 판정 결과가 바뀌지 않는다

---

### FR-304 판정 결과 목록 표시

**우선순위** P0

**적용 범위** FR-302에서 계산한 약제별 결과를 화면에 표시한다. 판정 계산과 일관성 기준은 각각 FR-302·303을 따른다.

**입력**

- FR-301의 약제 목록에 FR-302를 각각 적용한 결과 배열

**처리**

1. 상태별로 정렬한다. 순서는 `GREEN` → `AMBER` → `UNKNOWN` → `RED`.
2. 전체 약제를 표시한다. 판정 결과로 걸러내지 않는다.
3. ①②③ 영역과 ④ 영역을 시각적으로 구분한다.

**출력**

- 약제별 판정 카드 목록

**수락 기준**

- `RED` 약제도 화면에 표시되며 사유가 함께 보인다
- ①②③과 ④가 구분되어 표시된다

### FR-305 판정 근거 표시

**우선순위** P0

**입력**

- 체크별 판정 사유, 확보한 근거 원문, 데이터 기준일

**출력**

- 각 체크 항목별 사용기준·등록정보·반복규칙의 근거 원문
- 데이터 기준일

**수락 기준**

- 모든 판정 화면에 기준일이 표시된다
- 확보한 근거 원문을 그대로 표시한다. 원문 해석 실패 시에도 원문을 확인할 수 있다
- 근거가 없는 조건은 확인 필요로 표시하고 부족한 정보를 안내한다. 원문을 만들어 채우지 않는다
- 자료 자체가 없으면 해당 체크에 「확인 필요: 사용기준 자료 없음」처럼 부족한 정보의 종류를 표시한다. 등록·계열·반복규칙 등 다른 자료가 없으면 해당 자료명을 표시한다
- 확보한 근거 원문·출처·데이터 기준일은 표시하고, 없는 항목은 「근거 원문 없음」·「출처 확인 불가」·「데이터 기준일 확인 불가」처럼 구분한다. 없는 값은 만들지 않는다
- 실제 데이터 기준일을 확인할 수 있으면 근거 원문이 없더라도 해당 기준일을 표시한다. API에서 누락값을 표현할 방식은 기술 문서에서 정한다

### FR-306 대안 약제 제시

**우선순위** P0

**입력**

- 현재 약제의 작용기작 코드
- 동일 (작물, 병해충)의 등록 약제 목록
- 구역 살포 이력

**처리**

1. 현재 약제와 작용기작이 다른 등록 약제를 대안 후보로 확인한다.
2. 각 후보에 FR-302를 적용한다.
3. `GREEN` 상태인 것만 반환한다.

**출력**

- 대안 약제 목록 (품목명, 작용기작 코드, 잔여 횟수)

**예외**

- 대안 0건: 「사용 가능한 대안 약제가 없습니다. 농업기술센터에 문의하세요」 출력

**수락 기준**

- 대안 목록에 현재 약제와 같은 작용기작 코드가 포함되지 않는다
- 대안이 0건일 때만 문의 안내가 출력된다

**비고**
다작용점 약제의 우선 표시는 적용 대상·근거를 확인한 뒤 결정한다. 현재 확정된 정렬 규칙으로 적용하지 않는다.

### FR-401 살포 이력 기록

**우선순위** P0

**입력**

- 실제 살포한 구역 ID, 약제 ID, 살포일 (기본값 오늘, 사용자 확인 필수)
- 병해충 ID (선택)
- 판정 화면에서 이동한 경우 관련 판정 정보. 과거 이력 직접 입력에는 판정 결과가 필수가 아니다.

**처리**

1. 사용자가 실제 살포한 구역·약제·날짜를 확인하고 「살포 기록 저장」을 누른다.
2. 확인한 실제 살포 사실을 기록한다.
3. 판정 화면에서 직접 기록·과거 이력 직접 입력·포장지 촬영(P1)의 입력 경로를 구분한다.
4. 연결할 판정 정보가 있으면 함께 보관한다. 살포 이력의 사실 정보와 구분한다.

**출력**

- 기록 완료 안내
- 갱신된 잔여 횟수와 작용기작 카운트

**예외**

- 실제 살포 날짜·구역·약제 미확인: 부족한 항목을 표시하고 확인 후 저장한다.
- 같은 구역·약제·날짜 조합의 기존 기록이 있으면 중복 후보로 안내하고 해당 기록을 보여준다.
- 사용자는 「기존 기록 확인」·「실제 별도 살포로 저장」·「돌아가기」 중 하나를 선택한다. 별도 살포라고 확인한 경우에만 새 기록을 저장하며, 같은 저장 작업의 재시도는 별도 살포로 취급하지 않는다.
- 저장 실패·결과 불명확·재시도는 4.6절의 규칙에 따른다. 같은 저장 작업의 재시도와 실제 별도 살포 기록은 구분한다.

**수락 기준**

- 버튼을 누르지 않으면 기록되지 않는다
- 실제 기록은 해당 구역의 유효 이력에 반영되며, 확인 가능한 범위의 횟수·계통 집계를 다시 계산한다
- 이번 사용 1회 가정을 이미 포함한 판정 표시값에 저장한 1회를 다시 더하지 않는다
- 이력이 추가되어도 부족한 재배 기간·누락 이력·계열 정보가 자동으로 해결된 것으로 간주하지 않는다
- 사용 예정이나 구매 사실만으로 살포 이력을 생성하지 않는다
- 중복 후보가 있어도 기존 기록을 자동 삭제하거나 새 기록을 자동 저장하지 않는다. 기존 기록 확인·돌아가기는 새 기록을 생성하지 않는다
- 사용자가 실제 별도 살포로 확인하고 저장한 건은 별도 기록으로 반영되며, 같은 저장 작업의 재시도로 기록이 추가되지 않는다

**저장 실패·재시도 수락 기준**

- 저장 성공이 확인된 기록만 완료로 안내한다
- 미저장이 확인된 실패 후 입력값을 유지하고 수정·재시도할 수 있다
- 응답을 받지 못한 경우 저장 여부를 다시 확인하고, 같은 저장 작업을 여러 번 시도해도 이력·집계에 한 번만 반영한다

### FR-402 살포 이력 취소

- 취소 실패·결과 불명확·재시도는 4.6절의 규칙에 따른다.

**출력**

**수락 기준**

- 원래의 유효 이력으로 돌아오면 같은 기준일·규칙에서 이전 집계 결과로 돌아온다. 이력이 0건이 되면 ③④는 확인 필요다.

### FR-403 살포 이력 목록 조회

**우선순위** P0

**입력**

- 구역 ID, 기간 (기본값 현재 작기)

**처리**

- 재배 기간을 구분할 수 있으면 현재 작기의 이력을 기본 조회한다. 취소된 기록은 유효 집계에서 제외한다.
- 정식일 등 기간 정보가 부족하면 사용자가 조회 기간을 지정하거나 해당 구역의 기록을 확인할 수 있게 한다. 이 목록을 현재 작기 전체 이력으로 간주하지 않는다.
- 정식일을 추가·수정한 뒤에는 변경된 재배 기간에 포함되는 기록과 기간 밖 기록을 구분해 확인할 수 있게 한다. 기간 밖 기록도 보존한다.
- 재배 기간의 기록 누락 여부를 확인할 수 있게 하고, 누락이 있거나 확인하지 못한 경우 해당 상태를 표시한다.
- 누락이 있거나 확인하지 못한 경우, 필요한 이력을 보완하거나 정보를 확인할 경로를 제공하고 관련 ③④를 확인 필요로 표시한다. 누락이 없다는 답변 뒤에도 재배 기간·약제·사용기준·반복규칙 등 계산 근거가 부족하면 해당 체크는 확인 필요를 유지한다. 충분한 이력의 범위는 8절의 검증 항목을 따른다.

**출력**

- 구역, 실제 살포일, 약제명, 작용기작 코드, 입력 경로, 취소 여부

**수락 기준**

- 정식일이 확인된 구역은 현재 작기 기준으로 조회하고, 미입력 구역도 기록 목록을 확인할 수 있다
- 취소 여부와 구역을 구분할 수 있으며 취소된 기록이 유효 집계에 포함되지 않는다

### FR-404 과거 살포 이력 직접 입력

### FR-501 구역 작용기작 계통 사용 비중

- 구역별 작물·기록 요약·확인 가능한 계통 사용 정보

**수락 기준**

- 밭 화면에서 구역명·작물·최근 살포일을 구분하고, 구역마다 기록 없음·정보 부족·확인 가능한 계통 사용 비중을 확인할 수 있다
- 약제를 선택하지 않은 구역 전체에 단일 약제의 최종 판정 상태를 일반화하지 않는다

---

### FR-503 행정구역 계통 사용 비중 지도

**우선순위** P2

**입력**

- 행정구역 코드, 기간

**처리**

- 해당 행정구역의 유효한 실제 살포 이력을 합산해 계통별 사용 비율을 계산한다. 취소된 기록과 판정의 이번 1회 가정은 제외한다.

**출력**

- 행정구역별 최다 계통과 비율

**예외**

- 표본 수가 기준 미만이면 표시하지 않는다 (기준값 협의 필요)

**수락 기준**

- 개별 농가를 식별할 수 없는 형태로 집계된다

### FR-504 논문 실측값 표시

**우선순위** P1

**입력**

- 선택한 작물·병해충·약제 성분 또는 작용기작

**처리**

- 확보한 논문에서 대상 작물·병해충·성분에 해당하는 실측값과 시험 조건을 확인한다. 작용기작이 같다는 이유만으로 다른 성분의 측정치를 같은 약제의 값으로 표시하지 않는다.
- 비교 가능한 여러 연도의 측정치가 있으면 연도별 그래프로 표시한다. 연도별 자료가 없으면 확보한 측정치를 표 또는 개별 값으로 표시한다.

**출력**

- 자료에 맞는 실측값 그래프 또는 표·개별 값. 연도별 사멸률 자료가 있는 경우에만 연도별 사멸률 그래프를 표시한다.
- 측정 대상 작물·병해충·약제 성분, 채집 지역·측정 연도, 농도·측정 시점 등 해석에 필요한 시험 조건과 지표의 의미
- 출처 (저자, 논문명, 학회지, 권호)

**예외**

- 데이터 없음: 화면을 표시하지 않는다

**수락 기준**

- 출처가 없는 수치는 표시되지 않는다
- 다른 작물·병해충·성분 또는 비교할 수 없는 시험 조건의 값을 한 추세로 연결하지 않는다
- 확보하지 않은 연도의 수치를 만들어 채우지 않는다
- 이 값을 사용자 구역의 판정에 사용하지 않는다
- 「표시 전용」임이 화면에 명시된다

**비고**
논문 실측값은 특정 작물·해충·지역의 측정치다. 다른 조건에 대입하면 근거가 없어진다. 판정 경로와 분리한다.

### FR-601 기본 날씨 정보 표시

**우선순위** P0

**입력**

- 구역 좌표

**처리**

1. 선택 구역의 위치에 해당하는 기상청 단기예보의 시간대별 강수 예보와 발표 시각을 조회한다.
2. 네 개의 체크와 함께 참고 정보로 표시하되, 날씨를 반영한 별도의 살포 가능 판정을 만들지 않는다.

**출력**

- 구역 위치 기준의 시간대별 강수 예보, 예보 발표 시각, 출처

**예외**

- API 실패: 날씨 조회 실패 상태를 표시한다. 네 개의 체크와 기록 흐름은 계속 사용할 수 있다.

**수락 기준**

- 기상청 조회 실패 시 실패 안내를 표시하고, 이미 준비한 자료로 네 개의 체크 조회와 살포 기록·목록·취소를 계속 사용할 수 있다
- 구역 위치·예보 발표 시각을 확인할 수 있고, 예보만으로 살포 가능·불가를 추가 판정하지 않는다

---

### FR-602 포장지 OCR을 통한 살포 이력 입력 보조

**우선순위** P1

**입력**

- 농약 포장지 이미지
- 사용자가 확인한 실제 살포 구역·날짜

**처리**

1. 이미지에서 문자를 인식한다.
2. 약제명에 해당하는 문자를 읽고 기존 약제 데이터와 대조해 후보 목록을 제시한다.
3. 사용자가 실제 제품을 선택하고, 실제 살포한 구역·날짜를 확인 또는 직접 입력한다.
4. 사용자가 「살포 기록 저장」을 누르면 FR-401의 기준으로 저장한다.

**출력**

- 약제 후보 목록, 사용자 확인·저장 후 실제 살포 기록

**예외**

- 인식 실패·후보 없음·사용자가 후보를 확정하지 못함: 직접 검색·입력으로 전환한다.
- 포장지의 제조일·유효기간 등을 실제 살포 날짜로 사용하지 않는다. 실제 살포 날짜는 사용자가 확인한다.

**수락 기준**

- 인식 결과를 사용자 확인 없이 저장하지 않는다
- 포장지 촬영을 통한 입력 경로로 구분된다
- 판정 입구의 약제 선택을 OCR로 대체하지 않는다. OCR은 이력 입력 화면에서 사용한다.
- 실제 살포 구역·날짜를 확인해야 저장할 수 있고, 입력된 값이 있더라도 사용자가 확인한다
- 이 기능이 동작하지 않아도 FR-401·404의 직접 기록 경로가 정상 동작한다

**검증할 내용**

- 소규모 포장지 표본과 정답 상표명·품목명·회사명·출처를 대조해 약제 후보 연결과 실패 사례를 확인한다.
- 후보 확인·실제 살포 정보 입력·직접 입력 전환의 사용 흐름과 인식 결과를 검증한다. 표본 결과를 전체 인식률로 제시하지 않는다.

---

### FR-603 희석배수·소요약량 계산

**우선순위** P1

**입력**

- 약제의 희석배수, 방제기 용량

**처리**

- 확인된 원자료의 제형·단위·사용기준에 맞는 계산 방법을 적용한다. 제형과 단위에 관계없이 하나의 식으로 계산하지 않는다.

**출력**

- 필요 약량

**수락 기준**

- 희석배수가 없는 약제는 계산 결과를 표시하지 않는다
- 제형·단위·사용기준을 확인할 수 없으면 계산 결과를 표시하지 않는다. 세부 계산은 담당자가 원자료를 확인해 확정한다.

## 7. 화면·기능 영역별 요구사항 매핑

이 표는 기능을 사용하는 화면·영역을 연결한다. 각 행이 반드시 독립 페이지를 뜻하지는 않는다. 표에서 별도로 표시하지 않은 기능은 P0다.

| 화면·기능 영역 | 포함 요구사항 |
|---|---|
| 밭·구역 등록 및 작물·정식일 수정 | FR-101 경계 조회, FR-102 균등 분할·선 그리기·경계 수정, FR-103 작물·정식일 지정·수정 |
| 내 밭 | FR-501 구역별 계통 사용 비중, FR-502 구역 요약, FR-403 구역 이력 확인 |
| 병해충 선택·매개충 안내 | FR-201~205 증상 부위·후보·직접 선택·이름 검색·매개충 안내 |
| 약제 목록·판정 | FR-301 등록 약제 조회·검색, FR-302 네 개의 체크, FR-304 결과 목록, FR-305 근거, FR-306 대안, FR-601 기본 날씨. FR-401 기록 입력으로 이동. 희석 계산 FR-603은 P1 |
| 이력 입력·조회·취소 | FR-401 저장·중복 후보 확인, FR-402 취소, FR-403 목록·기간·누락 여부 확인, FR-404 과거 직접 입력. 포장지 OCR 입력 보조 FR-602는 P1 |
| 논문 실측값 표시 | FR-504 (P1). 자료에 맞는 그래프·표·개별 값과 시험 조건·출처 표시 |
| 행정구역 사용 비중 지도 | FR-503 (P2 고도화) |

FR-303의 판정 일관성과 4절의 판정·표기 규칙은 모든 판정 결과에 적용한다. 4.6절은 관련 저장·취소에 적용하고, 비기능 요구사항은 각 요구사항의 적용 범위에 따라 위 화면·영역에 공통으로 적용한다.

FR-401이 판정과 이력 입력에 함께 연결되는 이유는 판정 화면에서 시작한 기록 입력에도 동일한 저장 규칙을 사용하기 때문이다.

## 8. 미확정 사항

아래는 첫 버전의 판정·기록·구역 분할에 영향을 주는 확인 항목이다. 확정된 사용 흐름은 개별 요구사항에 반영했으며, 남은 계산 기준을 임의로 통과 조건으로 해석하지 않는다.

| ~~③횟수의 합산 단위 (성분 / 품목)~~ | — | **해결 2026-10-15. 성분 기준.** 4.x절·[DB 시드 전달서 4절](../technical/DB_시드_전달서.md) |
