# 팜가디언 PRD

## 1. 서비스 개요와 해결할 문제

**농약을 뿌리기 전에, 선택한 약제를 지금 이 구역에 사용할 조건이 갖춰졌는지 공공데이터와 살포 이력으로 확인하는 모바일 우선 반응형 웹 서비스.**

사용자는 작물·병해충 등록정보, 수확 관련 기준, 사용횟수, 작용기작을 함께 대조해야 한다.  
 구역별 이력이 정리되지 않으면 사용횟수와 같은 계통의 반복을 확인하기 어렵다.  
팜가디언은 이 정보를 한 흐름에서 확인하고 근거를 볼 수 있게 한다.  

- 대상 작물: 감자·배추·토마토 3종.
- 핵심 자료: PSIS의 등록·사용기준, NCPMS의 병해충 도감, 팜맵의 경작 경계, 기상청 단기예보, 사용자의 구역별 살포 이력.

## 2. 대상 사용자와 페르소나 초안

주 사용자는 현장에서 약제의 사용조건을 확인하고 구역별 살포 이력을 관리하는 농가다. 아래 네 인물과 해결할 문제는 사용자 조사 전의 기획 초안이다.


| ID   | 인물     | 유형                        | 농약정보 이해                   | 평소 기록 습관                  |
| ---- | ------ | ------------------------- | ------------------------- | ------------------------- |
| P-01 | 이승준(A) | 처음 재배하는 사용자               | 병해충·약제 용어가 낯섦             | 기록을 아직 시작하지 않음            |
| P-02 | 박민수(B) | 익숙한 약제를 사용하며 기억에 의존하는 사용자 | 익숙한 제품은 알지만 계열 구분에 설명이 필요 | 살포 날짜·횟수는 기억에 의존하고 일부만 기록 |
| P-03 | 김서현(C) | 살포 기록을 꾸준히 남기는 사용자        | 약제의 안전사용기준·계열 해석에 설명이 필요  | 살포 후 구역·약제·날짜를 꾸준히 기록     |
| P-04 | 정지훈(D) | 여러 구역을 관리하는 사용자           | 작물·약제 정보에 익숙함             | 구역별로 약제·살포 날짜를 구분해 기록     |


인물별 처한 상황·목표·겪고 있는 어려움·사용 순서는 [팜가디언 페르소나 문서](팜가디언_페르소나.md)에서 확인한다.

## 3. 제품 목표

- 사용자가 구역 → 병해충 → 약제 → 판정 → 기록의 핵심 흐름을 완료한다.
- 확인된 조건과 근거가 부족한 조건을 구분해 이해한다.
- 수확 가능 날짜, 남은 횟수, 계통 반복과 근거를 확인한다.
- 기록·취소 후에도 구역별 횟수와 계통 카운트가 일관되게 반영된다.

## 4. 핵심 사용자 흐름과 화면

### 4.1 전체 흐름


| 단계      | 사용자 행동                   | 화면에서 확인할 것                |
| ------- | ------------------------ | ------------------------- |
| 밭·구역 등록 | 주소로 경작 경계를 찾고 구역·작물을 지정  | 실제 경계, 구역명·작물·정식일         |
| 내 밭     | 사용할 구역 선택                | 선택한 구역, 작물, 구역 상태·기록      |
| 병해충 선택  | 증상 부위·도감을 보고 직접 선택하거나 생략 | 사진·이름 후보, 선택하지 않고 진행하는 경로 |
| 약제·판정   | 약제를 선택하고 네 개의 체크 확인      | 상태·사유·날짜·횟수·원문·기준일·대안     |
| 기록·이력   | 명시적으로 기록하고 목록 확인·취소      | 기록한 구역·약제·날짜, 취소 반영 결과    |

밭·구역 등록에서는 팜맵으로 조회한 실제 경작 경계를 기준으로 분할 개수·방향을 선택해 균등 면적으로 나누거나, 직접 선을 그어 구역을 나눈다. 두 방식 모두 분할 후 경계를 드래그해 수정하고 최종 구역을 저장할 수 있다. 경계를 수정한 뒤에는 균등 면적을 유지할 필요가 없다.


정식일은 입력을 권하되 선택 항목으로 두고, 미입력 상태에서도 구역을 등록하고 나중에 날짜를 추가할 수 있다. 정식일 없이 적용할 수 있는 사용기준이면 ② 수확 가능 날짜를 계산한다. ③은 이번 재배 기간을 구분할 정보가 없으면 확인 필요로 표시하며, ④도 해당 반복규칙에 필요한 정보가 부족하면 확인 필요로 표시한다.

기록 버튼은 실제 살포한 구역·약제·날짜를 저장하는 ‘살포 기록 저장’으로 둔다. 실제 기록만 횟수·계통 집계에 반영하고, 잘못 입력한 기록은 취소할 수 있다. P0에는 과거 살포 이력을 직접 입력하는 경로도 포함하며, 과거 판정 화면을 다시 거치지 않고 기록할 수 있다.

정식일을 추가·수정해도 기존 살포 기록은 보존하고, 변경된 재배 기간에 포함되는 기록을 확인할 수 있게 한다. 기록 누락 여부를 확인하고, 누락이 있거나 계산에 필요한 근거가 부족하면 관련 ③④를 확인 필요로 표시하며 이력 보완·정보 확인 경로를 제공한다. 누락이 없다는 사용자 답변만으로 통과시키지 않는다. 같은 구역·약제·날짜의 기록이 있으면 기존 기록 확인·실제 별도 살포로 저장·돌아가기 중 선택하며, 같은 저장 작업의 재시도는 한 번만 반영한다.

포장지 OCR은 P1 살포 이력 입력 보조 기능이다. 포장지 촬영 → 약제명 후보 확인·선택 → 사용자가 실제 살포 구역·날짜 확인 또는 입력 → 살포 기록 저장 순서로 진행한다. 포장지의 제조일·유효기간 등을 실제 살포 날짜로 사용하지 않는다. 판정할 약제는 이름 검색·목록 선택으로 고른다.

병해충 발생시기는 출처·기준 시점과 함께 참고 정보로 표시하며, 발생시기만으로 선택 후보를 제외하지 않는다. 도감에 없고 등록약 자료에 있는 병해충도 기본 이름 검색으로 선택할 수 있다. 사진·설명이 없으면 없다고 표시한다.

바이러스 항목에서는 원자료로 확인된 매개충 정보를 안내하고, 사용자가 매개충을 직접 선택하면 해당 작물·매개충에 등록된 약제의 네 개 체크로 연결한다. 연결 자료가 없으면 그 사실을 표시한다. 매개충의 약제 사용조건을 바이러스 치료 효과로 설명하지 않는다.

판정 화면에서 선택한 구역 위치 기준의 시간대별 강수 예보와 예보 발표 시각을 함께 확인할 수 있다. 날씨 조회에 실패해도 네 개의 체크는 계속 작동하며, 날씨 조회 실패 상태를 표시한다. 날씨를 반영한 별도의 살포 가능 판정은 현재 범위에 포함하지 않는다.

### 4.2 첫 시연: 배추의 약제 확인부터 기록·취소까지

P-03의 대표 상황으로, 등록된 배추 시험 구역에서 시작한다. 수집한 배추·배추좀나방 원자료를 대조해 약제와 규칙을 확정하고, 실제 농가 기록과 구분한 시험 이력을 사용한다.

1. 사용할 배추 구역을 선택한다.
2. 도감에서 배추좀나방을 선택하고 등록 약제를 고른다.
3. 네 개의 체크와 수확 가능 날짜·남은 횟수·같은 계통의 사용횟수를 확인한다.
4. 체크별 근거 원문과 데이터 기준일을 확인한다.
5. 시험 기록을 저장하고 해당 구역의 이력과 횟수 변화를 확인한다.
6. 방금 기록을 취소하고 이전 이력 기준의 횟수로 돌아오는지 확인한다.

이어서 이력 0건·병해충 미선택 사례와 같은 계통의 반복규칙 초과 사례를 보여준다. 시연 전 원자료를 대조해 시험 날짜·규칙과 기록 전후에 표시할 결과를 확정한다. 전체 P0 완료에는 밭·구역 등록도 포함된다.

## 5. 기능 범위와 우선순위

P0는 기본 흐름에 반드시 필요한 기능, P1은 P0 완료 후 검토할 추가 기능, P2는 기본 서비스 완성 후 별도 착수 합의로 진행할 고도화 기능이다.


| 기능 | 우선순위 |
|---|---|
| 밭·구역·작물·정식일 관리 | P0 |
| 도감·기본 이름 검색·매개충 안내와 사용자의 병해충 선택·미선택 진행 | P0 |
| 약제 목록과 등록·시기·횟수·작용기작 판정 | P0 |

직접 병명·발생·수확시기·저항성 수준을 산출하는 모델, 관수·시설 제어, 약효·약해 판정, 상담사 전용 계정·관리자 화면은 현재 범위에 포함하지 않는다.



## 6. 판정 원칙과 품질 조건

### 네 개의 체크


| 체크     | 사용자에게 답할 질문              |
| ------ | ------------------------ |
| ① 등록   | 이 작물·병해충에 등록된 약제인가?      |
| ② 시기   | 오늘 살포하면 어느 날짜부터 수확 가능한가? |
| ③ 횟수   | 이번 작기에 몇 번 남았는가?         |
| ④ 작용기작 | 같은 계통을 반복했는가?            |


③④는 선택한 약제를 이번에 1회 사용한다고 가정해 기준 충족 여부를 확인한다. 화면에는 현재 남은 횟수와 이번 사용 후 남을 횟수를 구분해 표시한다. 실제 이력은 사용자가 기록을 저장할 때 반영하며, 이력 0건의 확인 필요 원칙은 유지한다.

④는 계통 반복규칙을 확인한다. 약효나 실제 저항성 수준을 보증하지 않는다. 계통 사용 비중도 기록에서 센 값이며 저항성 수준을 뜻하지 않는다.

판정 상태는 **가능(GREEN)·주의(AMBER)·불가(RED)·확인 필요(UNKNOWN)·해당 없음(NA)**다.
괄호 안은 API에서 사용하는 상태 코드이며, 화면에는 한국어 상태명을 표시한다. 최종 상태 우선순위는 **RED &gt; NA &gt; UNKNOWN &gt; AMBER &gt; GREEN**이다.

해당 없음은 **그 체크 항목이 이 약에 적용되지 않는 경우**다. 심을 때 땅에 넣는 약에는 수확 전 일수라는 항목이 없다. 값을 모르는 확인 필요와 구분하며, 둘 다 통과로 올리지 않는다 (2026-10-27 확정, [제품쟁점 11번](../internal/팜가디언_제품쟁점.md)). 화면에는 해당 없음을 「심을 때」로 표시한다.


### 반드시 지킬 규칙

1. 살포 이력 0건이면 ③④는 UNKNOWN으로 표시한다. GREEN으로 표시하지 않는다.
2. 병해충 미선택이면 ①은 UNKNOWN. ②③④는 각각 필요한 정보로 판단한다.
3. 원문 해석에 실패하면 해당 체크는 UNKNOWN이며 원문을 그대로 보여준다.
4. RED·AMBER에는 작용기작이 다른 대안을 함께 제공한다.
5. 농업기술센터 문의는 대안이 0개일 때만 안내한다.
6. 판정에는 근거 원문과 데이터 기준일을 반드시 제공한다.
7. 수확 가능일은 일수 대신 날짜로 제공한다.

국내 계열 코드를 먼저, 국제 코드를 괄호 안에 표시한다. 판정은 공공데이터 조회와 규칙 계산으로 설명한다. 빈 기준값을 임의로 제한 없음으로 해석하지 않는다. **빈칸에는 두 종류가 있다.** 값을 모르는 빈칸은 확인 필요로, 항목 자체가 적용되지 않는 빈칸은 해당 없음으로 나눈다. 비어 있는 값을 다른 줄에서 빌려와 추측하지 않는다. 기준이 비어 있거나 생육단계 등 추가 조건의 충족 여부를 확인할 수 없으면 해당 체크만 확인 필요로 표시하고 원문과 부족한 정보를 제공한다. 약제는 목록에서 확인할 수 있으며 다른 체크는 각자의 근거로 판단한다.

### 품질 조건

- 모바일 우선 반응형 웹으로 휴대폰·태블릿·PC에서 핵심 흐름을 사용할 수 있다.
- 실제 경작 경계와 선택 구역을 확인할 수 있다.
- 동일 입력·동일 원자료·규칙·데이터 기준일이면 동일한 판정을 제공한다.
- 판정 응답시간 목표는 미확정이며, 판정 기능 구현 후 측정 결과를 바탕으로 팀이 확정한다.
- 외부 공공 API 장애 시에도 이미 적재한 데이터로 판정·시연할 수 있다.
- 공공데이터 출처를 표시하고 지역 집계에 농가 식별 정보를 노출하지 않는다.

## 7. P0 완료 기준

- 등록한 밭에서 구역·작물을 확인하고 병해충·약제 선택 → 판정 → 명시적 기록 → 조회·취소까지 진행할 수 있다.
- 과거에 실제 살포한 구역·약제·날짜를 직접 입력하고 목록에서 확인·취소할 수 있다.
- 판정 화면에서 구역 위치 기준의 강수 예보와 발표 시각을 확인할 수 있으며, 날씨 조회 실패 시에도 판정이 정상 작동한다.
- 발생시기를 이유로 병해충 선택을 막지 않고, 도감에는 없지만 수집한 등록약 자료에 있는 병해충도 이름으로 찾아 선택할 수 있다. 확인된 바이러스·매개충 연결에서는 사용자가 매개충을 선택해 그 매개충의 등록 약제 조건을 확인할 수 있다.
- 근거와 이력이 갖춰져 모두 통과하는 사례, 반복규칙 초과 사례, 횟수 소진 사례에서 정해진 상태·사유가 표시된다.
- 이력 0건, 병해충 미선택, 원문 해석 실패에서는 해당 체크가 확인 필요이며 부족한 정보와 원문을 볼 수 있다.
- 불가·주의에는 다른 계통의 대안을 표시하고, 대안이 없을 때만 문의를 안내한다.
- 체크별 원문·기준일과 수확 가능 날짜를 확인할 수 있다.
- 기록·취소 후 유효한 구역별 이력으로 횟수·계통 카운트·계통 사용 비중이 다시 계산된다. 이력 없는 구역은 기록 없음으로 표시된다.
- 모바일에서 핵심 흐름을 완료하고 선택 구역·상태·날짜·근거를 구분할 수 있다.
